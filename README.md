# Sathi — Care Coordination (PWA)

A React + Vite progressive web app for coordinating medication, inventory, purchases and transport for a shared care plan. Runs **standalone offline** (local-first IndexedDB) and is architected for server sync when the backend exists. See `docs/FRONTEND_STATUS.md` for the exact implemented scope.

## Scripts

| Script                   | Description                                                     |
| ------------------------ | --------------------------------------------------------------- |
| `npm run dev`            | Start the Vite dev server (PWA service worker enabled)          |
| `npm run build`          | Production build, including service worker + manifest (`dist/`) |
| `npm run preview`        | Preview the production build locally                            |
| `npm run lint`           | Run ESLint                                                      |
| `npm test`               | Run unit + component tests once (Vitest)                        |
| `npm run test:watch`     | Run Vitest in watch mode                                        |
| `npm run test:e2e`       | Run end-to-end browser tests (Playwright + Chromium)            |
| `npm run test:e2e:ui`    | Open the Playwright UI runner                                   |
| `npm run test:all`       | Run Vitest, then Playwright                                     |
| `npm run generate:icons` | Regenerate the PWA icon set from the inline SVG source          |

## App structure

```txt
src/
  app/         root router, session/plan guards, tab-bar shell
  screens/     Login, AccountRecovery, PlanSelector, CreatePlan, Dashboard,
               Medicines, MedicineForm, Schedule, PatientProfile, Members,
               Inventory, StockReceipt, StockAdjust, Purchases, PurchaseDetails,
               Transfers, Notifications, NotificationPreferences, SyncStatus,
               AuditHistory, Settings (+ tests)
  components/  shared UI kit (design tokens only)
  store/       zustand stores: session, plan context, medicines, members
  lib/
    db/        local-first IndexedDB model (standalone offline, sync-ready),
               cipher/device key helpers
    repo/      repositories: app, plan, medicines, schedule, inventory,
               members, purchases, transfers, notifications
    security/  sealed-payload envelope and secure fetch helpers (device-key)
  styles/      modular color-token system (themes/*.css)
  pwa/         manifest source of truth + validation tests
```

## Key behavior (current)

- **Standalone/local-first:** device profiles, plan-scoped IndexedDB, append-only ledgers for dose records/stock movements/audit where applicable, and a local `syncQueue` (no backend push/pull yet).
- **Medicines & schedule:** manual instructions only; dynamic dose times with per-dose quantity and meal timing (before/after/with/not specified); recording outcomes (given/missed/refused/other), corrections append with reason and latest correction is shown on schedule slots.
- **Stock:** receipts/consumption/adjustments via movement ledger; derived totals/low-stock flags. Inventory, receipt, adjust, purchase, and transfer screens provide local tracking workflows.
- **Security hardening:** restrictive CSP/referrer meta in `index.html`; device AES-GCM key helpers and sealed payload/envelope + `secureFetch` utilities for in-app unsealing/redacted handling. These are not yet wired to a live backend/sync transport (see `docs/FRONTEND_STATUS.md`).
- **PWA:** installable manifest/icons/service worker, offline shell, runtime caching.

## PWA setup

- **Manifest** — single source of truth in `src/pwa/manifest.js`, consumed by `vite.config.js` (`vite-plugin-pwa`) and validated by `src/pwa/manifest.test.js`.
- **Icons** — generated by `scripts/generate-icons.mjs` (sharp) into `public/`: `icons/icon-192.png`, `icons/icon-512.png`, `icons/icon-512-maskable.png`, `icons/apple-touch-icon.png`, plus favicons. Edit the SVG in the script and re-run `npm run generate:icons` after changing the artwork.
- **Service worker** — `generateSW` strategy with `registerType: 'autoUpdate'`, precaching of build output and runtime `CacheFirst` caching for images (30 days) and fonts (1 year). `devOptions.enabled` lets you test the SW in dev.
- **HTML meta** — `index.html` carries `theme-color`, app/meta tags, referrer policy, and CSP.

## Design system (color templates)

- The palette is a **modular token system** in `src/styles/`:
  - `themes/default.css` — "teal" (default, from `Project_Plan/Design.html`).
  - `themes/ocean.css`, `themes/sage.css`, `themes/dark.css` — additional variants.
  - `src/index.css` maps `--t-*` tokens into Tailwind (`@theme inline`), so utilities like `bg-brand`/`text-ink` follow the active variant at runtime.
  - `src/theme.js` — `initTheme()` / `setTheme()` controller (persists choice, honours OS dark-mode on first run).
- **Adding a variant**: copy a theme file, rename the selector, adjust values, add an `@import` in `src/index.css`, and register the name in `availableThemes` (`src/theme.js`). `src/styles/themes.test.js` enforces the token contract.

## Testing & CI/CD

- **Unit/component (Vitest + Testing Library, jsdom):** DB/repo/domain logic and screen/component behavior against real repos on fake-indexed-db; manifest/icon and theme-contract tests.
- **End-to-end (Playwright, Chromium):** routing guards, core care flow (sign in → create plan → add medicine with per-dose qty/meal → record/correct dose → sign out), rendering of core/care-management pages, sync security copy, and session/recovery checks. Specs live in `e2e/`.
- **Pre-push hook:** `simple-git-hooks` runs `npm run lint && npm test` (installed on `npm install`). Escape hatch (not recommended): `SKIP_SIMPLE_GIT_HOOKS=1 git push`.
- **CI:** `.github/workflows/ci.yml` runs lint/test/build on push/PR and a separate Playwright e2e job with report upload.
